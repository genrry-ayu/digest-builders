平台战略
模型与「马具」深度绑定，这是下一代平台战争的核心
Anthropic 平台团队两位负责人 Angela 和 Caitlin 在访谈中给出了一个被很多人忽略的判断：好的 agent 不是靠通用马具搭模型拼出来的，而是每一个模型都需要和自己深度定制的「马具」紧密配合。模型在进化，Agent SDK、tool calling 的方式、context 管理机制也必须跟着演化。这意味着 Cursor 那种一层抽象兼容多模型的做法，长远看可能会被各家的专有马具拉开差距。对创业者来说，选模型的同时就是选了平台——lock-in 不只是模型层的，更是架构层的。

产品范式
Agent 的「可生产化」比「能干活」难出一个量级
很多人都能用 Claude Code 或 Agent SDK 写一个能跑的原型。但真正让 agent 投入生产、24 小时不停机、处理长时异步任务、管理 session 状态和凭证——这些基础设施问题才是最大的坑。Anthropic 内部也反复踩过这些坑，最后决定把 Managed Agents 做成一个开箱即用的平台层。这个观察对任何想在企业里落地 agent 的团队都适用：别在基础设施上重复造轮子，那不是你的核心差异。

组织效能
Agent 需要「主人」——没人持续维护的 agent 会死掉
Dan Shipper 问了一个非常实际的问题：当公司里 agent 越来越多，谁来保证它们不僵化、不陈旧？Anthropic 的回答是「底层抽象化，上层交给具体团队」。他们发现最成功的 agent 不是由中央平台团队维护的，而是由业务团队在使用过程中自己迭代——甚至通过 Claude Code 直接改 PR。这个 pattern 值得每个有 agent 战略的公司思考：agent 的 ownership 应该是去中心化的，平台只需提供「安全的修改通道」。

技术治理
系统提示词改一行，Claude Code 可能变笨——Anthropic 踩过的坑值得所有人认真看
Anthropic Engineering 发了一篇罕见的详细 postmortem，讲述了 Claude Code 在过去一个月出现的三次「变笨」事件。原因包括：默认推理深度调低、session 过期后 reasoning 被错误清空、降低冗长的系统 prompt 影响了编码质量。每个改动都是合理的优化意图，但叠加起来效果像全面降级。这件事的教训远远不止给 Anthropic——任何基于 LLM 的产品都要意识到：prompt 层是脆弱的最前沿，系统性的 eval + 渐进式发布 + 足够的 soak period 是不可妥协的工程纪律。

02 — 议题 / Matters
Claude 开始「做梦」——Anthropic 的研究团队发现模型会在空闲时自我检查记忆
Peter Yang 总结 Alex Albert 访谈中提到：当 agent 不在执行任务时，它会回顾自身记忆、发现矛盾并修剪——这个源自睡眠中记忆处理的「dreaming」过程，可能是 LLM 自主迭代的关键方向。
Claude 新增日常类连接器：从 AllTrails 到 Uber Eats，agent 开始覆盖生活场景
Claude 的 connector 目录已超过 200 个，新增 AllTrails、Instacart、Uber、Tripadvisor 等生活应用。Claude 现在会在对话中动态推荐合适的 connector——这是从 work tool 向 everyday assistant 的关键一步。
Sam Altman 罕见夸赞 ChatGPT 最新更新「好太多了」
在首次公开承认 GPT-5 系列在某些场景有退化问题后，Altman 发推说 ChatGPT 的最新更新非常棒，为团队感到骄傲。获得 1.3 万点赞，但未透露具体改进细节。
Everlane 创始故事：从 Pinterest 竞争对手到时尚品牌再到破产
Linear 产品负责人 Nan Yu 回顾曾就职的 Everlane：疫情摧毁了它的「通勤装」市场，此后一直靠激进的融资条款维系。但他也指出 J.Crew、Madewell 甚至 Ray-Ban 都曾「死过」然后重生——品牌的生命力往往超出想象。
Agent 评估的终极形态：只剩「结果」和「预算」两个参数
Anthropic 平台团队对 agent 成功度的理想愿景：一切最终会压缩为「可验证的结果」和「预算」两个维度，其余全部由平台自动优化。这个框架值得所有 AI 团队作为产品设计的长远方向参考。
多 agent 架构开始分化——不同排列组合适用于不同类型的任务
Anthropic 观察到 advisor strategy、adversarial generation、分治组合等不同多 agent 架构各有专长深度研究适合一种，bug hunting 适合另一种。关键是将基础设施做成「乐高式」的，让用户自由组合。
