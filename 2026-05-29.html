产品范式

AI 越自动化，人类越不可或缺——"自动化悖论"在真实组织中被验证

Every 创始人 Dan Shipper 提出了一个反直觉但极有说服力的论点：自动化并不会消灭工作，而是产生更多工作。原因在于——AI 擅长让"昨天的专家能力"变得廉价普及（任何人都能 prompt 出代码/文章/设计），但这些东西看起来像样，实际上并不完全对。结果就是：组织中充斥着大量"接近但不精确"的输出，对真正专家的需求反而上升了。从 Every 自己的经历看：GPT-3 时代以来，他们从 4 人增长到 30 人，且还在招聘。这不是反自动化，而是揭示了自动化真正的动力学：AI 抬高的是地板，不是天花板。

系统设计

Anthropic 将 Agent 架构解耦为"大脑/双手/会话"三层，这可能是 agent 时代最重大的基础设施变革

Anthropic Engineering 发布了一篇深度技术文章，详细拆解 Managed Agents 的架构设计——将 agent 拆解为三个独立接口：会话（session，只追加的事件日志）、大脑（harness，调用 Claude 并路由工具调用的循环）、双手（sandbox，执行代码和编辑文件的环境）。这个设计彻底解决了三个长期痛点：容器崩溃不再导致会话丢失；推理延迟（TTFT）的 p50 下降约 60%、p95 下降超 90%；token 凭据不再暴露于沙箱环境。对于任何自己构建 agent 系统的人来说，这应该是 2026 年最重要的基础设施参考之一。

We virtualized the components of an agent: a session, a harness, and a sandbox. This allows the implementation of each to be swapped without disturbing the others. ... Our p50 TTFT dropped roughly 60% and p95 dropped over 90%.
— Anthropic Engineering · Scaling Managed Agents: Decoupling the brain from the hands
组织学习

Claude Code 的"变笨"事件是一次教科书级的组织学习案例

Anthropic 罕见地发布了详尽的公告，解释 Claude Code 过去一个月的质量退化问题——三个独立变更的叠加效应。最关键的不是它们做了什么，而是 Anthropic 如何解决：逐层追溯、做消融实验（移除 prompt 的每一行以理解影响）、然后彻底改进了系统提示词变更的管控流程。特别值得注意的是：一个新训练的系统提示词（将工具调用间字数限制在 25 词以内）导致了 3% 的评估降幅。在 AI 产品中，"减少啰嗦"和"保持智能"之间的张力远没有表面看起来那么简单。
