基础设施

每个 Agent 都需要一台属于它的计算机

Daytona CEO Ivan Burazin 提出一个看似简单但影响深远的论点：agent = digital knowledge worker，而 knowledge worker 必须有电脑。当前主流方案——让 agent 通过 API 操作现有系统——有一个根本缺陷：当一个 agent 被要求"登录银行取数据"时，它不会拒绝，而人类会说"不给"。

这意味着 agent 需要自己的隔离环境——sandbox——一个它可以完全控制的、独立的计算单元。Daytona 甚至为了性能抛弃 Kubernetes，自研调度器，因为对于长时间运行的 agent 工作负载，网络硬盘的 IOPS 瓶颈（数十万 vs. 本地磁盘的千万级）是致命的。当 agent 的生命周期从秒级扩展到天级，"沙箱即 agent 本体"将成为新的基础假设。

Ivan Burazin (Daytona CEO) — MAD Podcast
"When I think about agents, I think of them as digital knowledge workers. And to do anything as a knowledge worker, you do need a computer. My argument is that every agent will need at least one sandbox, sometimes more."
"The whole MCP model effectively is 'let's give agents access to tools,' and that has its place. But if you think about where this ends up: universal compute is a sandbox. And you give it a computer. What can it do? Whatever it can do."

工具链效率

Skill 文件就是新的"写文档"——但千万别写太长

Peter Steinberger（OpenClaw 创始人）的一条推文获得了单日近 4000 点赞：他写了一个 skill 找出所有"话多"的 skill——那些在 skill 描述里写小作文的，每次调用都要加载进 context，token 烧得飞快。token 效率正在成为 agent 工具链的关键指标。

这背后有一个更深刻的转变：OpenClaw 用 Rust WebAssembly（photon）替代了 Sharp + Jimp，从 140MB 砍到 2MB。对于 agent 运行时，"轻量化不是加分项，是生存条件"。当 agent 每天调用数百次 skill 时，依赖体积和描述长度直接转化为延迟和成本。效率优先的设计哲学正从代码质量领域渗透到 agent 开发的所有环节。

产品范式

MVP 时代终结：系统建设不再是拖延，而是交付的前提

Peter Yang 引用 Ryan Carson 的观点——过去我们说"别搭系统，先出 MVP"，现在完全反过来了。你必须花大量时间搭建文档体系、配置 cron job、编写 skill 文件，才能用 AI agent 实现 10 倍效率。

这解释了为什么"tokenmaxxing"（在低价无限量 AI 计划中疯狂使用 token）是合理的策略——当前的"畅吃 buffet"不会永远持续。同时这也暗示了 agent 开发的一个新常态：前期的元工作（文档、系统、技能定义）不是成本，而是杠杆。谁的系统建得越好，谁就能以更少的 token 做更多的事。

产业信号

AI 不会消灭工作——它会重新定义"足够好"的标准

Box CEO Aaron Levie 引用高盛 CEO 的观点，反驳了 AI 导致失业的悲观论调。核心逻辑是：自动化不会让产出变少，而是让每个人的期望值更高。几十年前如果告诉你打字速度能快 10 倍，你也会觉得"那以后没人需要打字员了"——但事实是大家只是要求写出更多的报告、做更深的研究、提供更个性化的服务。

这个论点的力量在于它指出了 AI 经济的一个自反性机制：当一部分玩家利用自动化提供了更好的产品，整个市场的基准就被抬高了。不跟进的人不是"没被替代"，而是失去竞争力。这可能是目前关于 AI 就业影响最冷静、最结构性的分析。

设计民主化

Codex 很强，但前端/设计类任务 Claude 仍是当前最优解

Peter Yang 在对比 Codex 和 Claude 后给出了一个简洁的判别：Codex 的浏览-测试闭环令人印象深刻，但只要涉及设计或前端，Claude 仍然胜出。这不是一个永久的结论，但它反映了一个重要的结构性差异——不同模型在"视觉-代码映射"能力上的分化。

对开发者而言，这意味着工具选择不再是"哪个模型最强"，而是"哪个模型最适合当前任务"。多模型策略正从理论变成日常实践。

Why AWS and Azure Cannot Run Autonomous AI – Ivan Burazin (Daytona)

Daytona CEO Ivan Burazin 在这期节目中从第一性原理出发解释"为什么每个 agent 都需要一台计算机"。他拆解了 agent stack 的完整架构（模型→沙箱→工具→MCP→记忆→编排），分享了 Daytona 抛弃 Kubernetes 自研调度器的原因——网络硬盘 IOPS 瓶颈在 agent 长时间运行时不可接受，本地磁盘才能提供千万级 IOPS。他还预测了 CPU 短缺的到来，以及 transformer 未必是智能的终极形态。

"If you think of most sandboxes and most VMs, they use the CPU RAM from the server and then the hard disk from a network drive. Whereas what we do is we actually use the CPU, RAM, and hard disk of the machine. The IOPS with a local drive is in the tens of millions. With a network drive, it's in the hundreds of thousands."
