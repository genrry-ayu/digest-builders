产品范式

"控制循环" 取代 "写提示词"，成为新一代 Agent 交互范式

Peter Steinberger 那条 "Don't prompt — design loops" 一天之内拿到 13,000+ 赞，这不是偶然。它精准戳中了一个正在发生的范式转移：从用户直接操控 Agent 完成单次任务，转向设计一套自动化流程——由 Agent 自主决策、执行、自检、循环。Y Combinator 总统 Garry Tan 推的 GBrain v0.42 具备追踪 "思维随时间变化" 的功能；Sam Altman 转发了 Codex "100 天每选一人 10 倍限额" 并评价 "interesting recursive loop"；就连 Peter Yang 的玩笑帖都在接 "设计循环" 的梗。这件事已经从极客圈蔓延到了主流通用社区。对产品构建者的启发是：下一波 AI 产品可以不再设计 UI 交互流程，而是设计 "Agent 工作循环" —— 定义目标、权限、反馈回路，然后放手让 Agent 自己去跑。

战略布局

Opus 正在成为 "长周期自主工作" 的事实标准——Claude Code 的隐形战场

Boris Cherny（Anthropic 的 Claude Code 负责人）详细列出了让 Opus 自主运行数小时/数天的五条建议：auto mode、动态工作流、/goal 或 /loop 持续推、云端运行可关笔记本、端到端自检闭环。这不是一篇技术教程，这是 Anthropic 在明牌打 "持久 Agent" 这个定位。与 GPT 系的 "一次回答一个任务" 不同，Opus 的策略是：让模型持续在后台工作，通过动态分治（动态生成数千个子 agent）完成超长任务。这和 Claude 新推出的 dreaming / outcomes / multiagent orchestration 一脉相承——前者是记忆层面，后者是质量和并行层面。对于平台构建者来说，这意味着两套 Agent 架构开始分野：任务型 vs. 持久型，而 Opus 坚定押注后者。这是否会成为下一代 Agent 系统的默认架构？

产业信号

模型分层已成定局——"路由层" 成为 Agent 栈中最具价值的中间件

Box CEO Aaron Levie 做了个精准判断：未来一两年内，用例一定会在模型家族之间分层——前沿模型处理高端任务，低成本模型处理大规模负载。关键的增量在于：能够高效地将工作负载路由到正确模型的那一层，将成为 Agent 领域的新硬问题。这不是在讲 "API 代理" 或 "模型选择器"，而是在定义一个新的抽象层——Agent 编排器需要做成本感知的智能路由，同时保证任务质量。Vercel 的 AI Gateway 每月恢复超过 1 万亿 token 的展示也佐证了一点：当规模上来后，路由/可靠性/可观测性这些基础设施的价值远超模型本身。

经济模型

AI 让软件开发变便宜了，但 GTN（进入市场）的成本没有变——这是创业者的新墙

Aaron Levie 的另一条长推值得每一个 AI 创业者细读：市场在一件事上判断错了——过去建企业软件很难，AI 让它变容易了，但企业软件公司的大头支出从来不是开发，而是 GTN（进入市场）。AI 并没有减少这点，在很多情况下甚至加剧了它——因为买方要在更拥挤、更复杂的方案中选择。Levie 的推论是：当软件变得更便宜更充足，发现能力和市场差异化（GTN）就变成了最难的部分。换句话说，如果你以为 "AI 能更快写代码" 就等于 "AI 公司更容易成功"，那可能算错了账。代码只是门票，分销才是战场。
▶ 查看原文
"The plurality of costs in most enterprise software companies is actually on GTM... AI hasn't reduced the need for that, and in many cases requires it even more now... If you make one thing cheaper and more abundant (development of software) then the new problem of discoverability and market differentiation (GTM) becomes the hardest part."
— Aaron Levie (levie), Box CEO · 来源
训练数据

高质量训练数据是突破模型边界的真正瓶颈——远非 "低端杂活"

前 Google Gemini/Veo PM Madhu Guru 提出了一个容易被忽视的观点：很多人以为训练数据是低技能的打杂工作——扫描笔记本、挖数据、打标签。但对于突破模型前沿来说，真正需要的是高经济价值任务的数据，而这些任务（除了软件工程）几乎都没有现成的文档——它们是多年积累的领域知识、互不通讯的遗留工具。这就是为什么我们有 SWE Agent，却没有 "知识工作 Agent"。这个观察和近期 Andrej Karpathy 等人对 "Agent 在复杂领域泛化困难" 的判断一致，也解释了为什么 Mercor 这类为公司创建训练数据的公司，在做的是极高杠杆、极稀缺的工作。
▶ 查看原文
"A common misconception is that training data is low skill, grunt work... The data required to advance the model frontier is the opposite... That's why we have SWE agents and not knowledge work agents yet. The companies creating this training data, such as Mercor, are doing extremely high-leverage, high-skill work."
— Madhu Guru (realmadhuguru), 前 Google Gemini/Veo PM · 来源

02 — 议题

Codex 的 "100 天 10 倍限额" 活动——降低试用门槛的潜在规律

Thibault Sottiaux（OpenAI Codex & ChatGPT）宣布接下来 100 天每天选一位用 Codex 做了 "令人印象深刻或极其有用" 工作的人，给予一个月的 10 倍用量额度。这种 "先让用户放手去试" 的方式，可能是测试产品极限、发现 killer use case 的巧妙策略。6,454 个赞 + 1,128 条回复说明关注度极高。

Claude Managed Agents 正式发布 dreaming / outcomes / multiagent 三大能力

dreaming 实现跨 session 记忆提炼和自省改进；outcomes 通过独立评分器让 Agent 根据标准自检自修正（内部测试成功率提升最多 10 个点）；multiagent orchestration 让主管 Agent 将任务分解给专用子 Agent 并行执行。Harvey（税务法律）完成率提升 ~6x，Every.com 的 Spiral 用 Haiku 接单 + Opus 写稿的混合架构值得参考。

IPOs 创造的财富如何回流到创新循环

Aditya Agarwal（South Park Commons GP，前 Dropbox CTO）回忆自己经历的两个 IPO 周期，指出主流叙事（买车买房去海滩）只是故事的一面，大量早期员工获得流动性后会去启动更疯狂的事情——创办新公司、资助新项目，维持硅谷的创新循环。伴随这轮 AI IPO 潮，这批 "新资金" 的去向值得关注。

从 "token 焦虑" 到 "token 优化"——企业 AI 预算心态正在转变

FPV Ventures 合伙人 Nikunj Kothari 观察到，几周内社群风向从 「怕用太多 token」 转向 「思考如何优化 token 使用」。但他认为企业仍应给员工慷慨的 token 预算以保持在前沿探索，否则太容易退回 "按老方法做事"。这是一个值得警惕的信号：当预算收紧，创造力会下降。

AI 教育的普及正成为新瓶颈

Garry Tan 转发了一条关于 "如何教人用 AI 工具" 已成为严重瓶颈的内容，并引用了 YC 为此建设的教程站点。当 AI 本身的能力增长快于用户对其的理解时，教育的规模化和产品化可能是一个被低估的市场。

Box 全面拥抱 Markdown + CLI + AI Agent 集成

Box 新版网页编辑器支持 Markdown，提供完整 CLI，Box Drive 可直接挂载为本地驱动器，让你在任何 AI 编辑器（Claude Code、Codex、Cursor、Obsidian）中直接操作文件。Aaron Levie 正把 Box 从 "企业网盘" 重塑为 "AI 工作流的文件层"。
