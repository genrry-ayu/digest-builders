产品范式
Agent 的"大脑与手脚"分离是工程架构的质变，不是微调
Anthropic 工程团队在 Managed Agents 的设计中提出了一个关键架构判断：将"大脑"（Claude 及其 orchestration loop）与"手脚"（沙箱、工具执行环境）彻底解耦。这不是性能优化，而是一种架构哲学的转变——引用 OS 设计中的"pets vs cattle"隐喻，把容器从需要"护理"的宠物变成了可替换的牲畜。直接的量化成果是 p50 首Token延迟下降约 60%、p95下降超 90%。更重要的是，这种解耦使得任何一层的失败都不会导致整体不可恢复——会话日志外置使得 brain 和 harness 都可以无状态重启。这是一篇值得每个做 agent 产品的团队反复阅读的文章。

Anthropic：Claude Code 问题回顾与改进措施
Anthropic 官方 · 2026年6月
Anthropic 发表了一份详细的事后分析，覆盖了 Claude Code 在 2026 年 4 月出现的两个关键问题。第一个 bug 来自一个 thinking history 清除机制的实现缺陷——本意是每个对话只在第一次重置时清除旧 reasoning 块，但标记位误设导致每次请求都只保留一个 reasoning 块，使模型在长时间会话中逐步丢失上下文记忆。第二个问题是系统 prompt 中加入的长度限制指令（"将工具调用间的文本控制在 25 词以内"），该指令在不同评估集上造成了约 3% 的能力退化。两项问题均已修复，所有订阅用户的用量限制已重置。团队同时宣布了系统 prompt 变更的管控加强措施。

Anthropic Engineering：Scaling Managed Agents — 将大脑与手脚解耦
Anthropic Engineering · Lance Martin, Gabe Cemaj, Michael Cohen
文章详细阐述了 Managed Agents 的架构演变：从最初的"大脑+手脚+会话"全部耦合在一个容器中，到三者通过清晰的接口（session、execute、provision）彻底解耦。关键架构决策包括：（1）将 harness 移出容器，使容器变成可丢弃的 cattle 而非需要护理的 pet；（2）将会话日志与上下文窗口分离，允许 brain 通过 getEvents() 任意回查历史；（3）令牌和凭据永远不进入沙箱，通过资源绑定或安全 vault 中介存取。解耦后的 p50 TTFT 下降约 60%，p95 下降超 90%。
