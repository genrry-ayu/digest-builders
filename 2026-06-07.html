Prompt Engineering

把任务写成问题，而不是指令

Swyx 提出了一个比「总是用 plan mode」更聪明的替代方案：把你的 prompt 末尾加个问号。看起来是个微不足道的技巧，但背后的逻辑很深刻——模型在没有被要求「盲目执行」时，会更自然地启动批判性思维，对任务的合理性做出判断而非机械响应。这暗示了当前 AI 交互中一个被低估的设计原则：你给的格式决定了模型思考的层次。指令格式触发执行模式，问题格式触发推理模式。区别仅在一个标点符号，但输出的质量天差地别。

Agent 平台

Agent 的持久化存储开始脱离生命周期绑定

Vercel CEO Guillermo Rauch 宣布了新的虚拟存储架构：Agent 的文件系统状态可以独立于 Sandbox 生命周期读写和挂载。这是一个被许多人忽略但关键的基础设施进化。当前大多数 Agent 平台的存储与计算实例强绑定，意味着 Agent 的「记忆」在每次重启后消失。Vercel 的这套方案把存储抽象成独立层，可同时挂载到 Builds、Functions、Sandboxes——这实际上是 Agent 从「无状态函数」走向「有状态实体」的底层前提。好戏还在后面。

知识工作自动化

AI 编程是自动化天花板，但它仍需要人类

Box 的 CEO Aaron Levie 给出了一个冷静的框架：编程已经拥有 AI 自动化最有利的条件（海量训练数据、高技术水平用户、可验证的产出、数字化的上下文），即便如此仍需要人类工程师监督。如果在这个最佳场景中人都没消失，那么其他知识工作领域的风险远比想象的低。这个论点没有否定 agent 的价值，而是划出了一条重要的边界——工程师不会因为 agent 而失业，而是会做更多的事。Levie 的深层判断是：真正的问题不是「谁会被替代」，而是「人类审阅能力如何跟上 agent 的生产速度」。

企业 AI 策略

不要为今天的能力定价，要为半年后的能力搭脚手架

前 Google AI 产品负责人 Madhu Guru 点出了一个常见的战略错误：企业 AI 团队总在为今天的模型能力和价格建系统。他建议——为当下的弱点搭脚手架来推进边界，赌下一代会原生解决这个脚手架问题，然后继续推进。反复识别和弥合模型差距的能力本身会成为护城河。这个「Build for the slope」的思路比分阶段升级更激进：你不是在等待模型变好，而是主动制造让模型不得不变好的条件。这不是被动的 roadmap，而是主动的博弈。

SaaSpocalypse · 播客精选

SaaS 末日是假象，开发者的数量正在从 3000 万奔向 10 亿

Figma 的开发者产品负责人 Matt Colyer 在 AI & I 播客中给出了一个反直觉的论断：所谓的 SaaS apocalypse 实际上是 SaaS 的金矿。他的核心论据——全球开发者数量将从三四千万膨胀到十亿甚至更多，因为 AI 大幅降低了软件生产门槛。但他也指出了一个被狂热叙事掩盖的真相：用 AI 写好一个 MVP 很容易，运行和维护它却是个烂摊子。Matt 自己就经历了这种痛苦——为自己写了个邮件 agent，然后发现要自己处理 SMTP 升级。最终他买的软件比以前更多了，因为「让别人替我运行那个 agent」才是更好的选择。换个角度看，AI 不是在杀死 SaaS，而是在创造更多需要被管理的软件——这也正是 SaaS 的机会。

Claude Cowork 限时翻倍额度 + 最佳实践场景
Claude 官方宣布未来一个月内 Cowork 的 5 小时速率限制翻倍；Boris Cherny 表示 Cowork 最擅长「大过聊天的任务」——跨几十个账号做研究、生成定期报告、收件箱分类和起草回复。
Codex 的「纸面瑕疵」在减少，采用率在飙升
OpenAI 的 Thibault Sottiaux 分享了一个简洁的观察：Codex 的小毛病曲线下降与采用率曲线上升的交叉点到了。同时提到更好的记忆系统 = 更短的 prompt = 每个 token 更多效用。
AI 技能的「自进化」工作流
Peter Yang 给出了一个系统化方法：给予上下文 → 触发入口 → 添加 evals → 加入记忆 → 构建一个编辑技能本身的技能。这是一个完整的 meta-skill 闭环，让 AI 工具随着使用自动变好。
GBrain 赋能 OpenClaw 和 Hermes Agent
YC 总裁 Garry Tan 预告了他几个月前开始筹划的项目——一个旨在帮助开发者学习「更快构建更好软件的最佳技术」的平台。同时提到 GBrain 正在给 OpenClaw 和 Hermes Agent 赋能。
