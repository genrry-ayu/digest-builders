产业基础设施
RL 训练正在从「不可能」变成「可租用的基础设施」
Cursor 联合 Fireworks 训练 Composer 2 的实践揭示了一个正在发生的范式转变——强化学习不再只是大实验室的专利。通过"异步流水线 + 全球分布式训练 + 模型增量同步"，一个拥有数万 GPU（而非数百万）的团队也能在合理成本内完成前沿级别的 RL 训练。三个关键工程突破值得关注：将 RL 中的训练与推理组件解耦，在不同集群和地理区域分别运行；利用模型权重的增量变化（而非全量）进行跨洲同步，将每次传输成本压缩 20 倍；以及在训练环节中内建了上下文自压缩能力——让模型在 RL 过程中学会如何总结自己的中间工作，从而在有限的上下文窗口内持续执行远超窗口长度的任务。这对于所有认真做 AI 产品的团队来说都是一个明确信号：现在就可以认真考虑 RL，基础设施的瓶颈正在被系统性拆除。

安全设计
Agent 安全的真正教训：你自己的代码才是系统中最弱的链路
Anthropic 长达万字的工程博客是一次难得的坦诚复盘。Claude 的三个产品（claude.ai / Claude Code / Cowork）采用了三种不同的隔离策略——临时容器、人机协同沙箱、全虚拟机——每种都有各自的失效模式。最值得关注的是：最严重的攻击面都来自 Anthropic 自己的自定义代理，而不是来自 seccomp、gVisor 或 hypervisor 这些久经考验的底层组件。员工钓鱼攻击（通过用户直接注入 prompt）和通过 api.anthropic.com 放行 API key 的 exfiltration 都不属于传统安全框架能处理的范畴。这对所有在 agent 上做产品的团队来说是一个沉重但重要的信号：环境层的确定性隔离才是最后的防线，模型层的概率防御永远会有疏漏。

工具生态
Agent 内生的"持续代码审查"正在成为新的开发标配
OpenClaw 作者 Peter Steinberger 发布的 autoreview 技能（接近 1000 点赞）可能是本周期最实用的单条分享。这个技能让 agent 在 PR 合并前自动执行深度审查——不只是在代码层面跑一遍 diff，而是持续数小时运行、反复推敲边缘情况。这不同于传统的 CI + 代码审查流程，因为 agent 有持续的注意力和上下文。与此同时，他的 Rastermill 库（Wasm+Rust 图像处理）和 Opus 音频处理的内嵌化展示了另一个趋势：随着 agent 需要处理更多类型的文件格式和数据，团队开始从外挂脚本转向自建 agent-native 的工具库。

Anthropic Engineering: How we contain Claude across products

Anthropic 发表了一篇重量级安全工程博客，深入讨论了 Claude 三大产品（claude.ai、Claude Code、Claude Cowork）各自不同的隔离架构。核心发现包括：用户批准疲劳导致 93% 的权限请求被自动通过，Claude Code 用户中使用 auto mode 后约 17% 的冒险行为未被阻止；最严重的安全漏洞均来自 Anthropic 自建的自定义组件（而非 seccomp/gVisor/hypervisor 等成熟底层）；员工钓鱼注入攻击在 25 次测试中成功了 24 次，暴露出模型层的概率防御对通过用户直接输入的注入无能为力。博客最后提出了三个关键原则：优先在环境层做确定性的隔离设计；根据用户的专业程度匹配隔离强度；警惕自建组件——你写的代码就是最薄弱的环节。

Training Data: How Cursor Trained Composer on Fireworks — Distributed Infrastructure for High-Performance RL

2026-05-26

Cursor 研究负责人 Federico 和 Fireworks 的 Dima 深度分享了 Composer 2 训练的幕后故事。核心要点：从 Kimi 2.5（1T 参数 MOE，30B active）基础上进行持续预训练 + 大规模 RL。RL 训练架构采用全球分布式设计——训练集群集中运行，推理集群分散在四个地区，甚至复用生产环境的空闲 GPU。关键工程突破包括模型增量同步（delta 压缩 20 倍）、针对 MOE 路由器的数值精度对齐（避免浮点运算非确定性导致训练发散）、以及将上下文自压缩纳入 RL 循环。他们还提到了 real-time RL——利用真实用户反馈信号在线更新模型。Federico 认为"RL 适用于所有场景，即使在 compute 很小的情况下也能有效调整模型的输出分布"。
